# Repository Audit — Recruitment Data Flow Map (Phase 0)

Date: 2026-07-18 · Auditor: orchestrator session (2 Explore agents + targeted reads)

## Framework & layout
- Repo root = `DPDPA Daily Brief/webapp/` (git root, canonical Desktop copy). **Next.js app root = `webapp/` inside it** — no `src/`. Outer root also holds the Python briefing pipeline, `docs/`, `templates/`, `tools/`.
- Next.js **16.1.7** App Router · React **19.2.3** · Tailwind **v4** (`@tailwindcss/postcss`) · TypeScript. Root `app/layout.tsx` mounts Header/Footer + Vercel `<Analytics/>`.
- Deploy: Vercel project `webapp`, `rootDirectory = webapp`. Flow: local → `next build` clean → branch → push → auto-deploy. Previews 401 to curl (verify via Vercel MCP).

## Route & component conventions
- Interactive tools use a **thin server `page.tsx` (metadata only) + `"use client"` client component**: `/assessment/recruitment/page.tsx` → `RecruitmentAssessmentClient.tsx`; `/discovery/page.tsx` → `DiscoveryClient.tsx` (+ co-located components + css).
- Assessment quiz routes are `noindex`; industry guide pages are indexed with breadcrumb/FAQ/speakable schema (`lib/schema.ts`), `Byline` (`components/seo/Byline.tsx`), `lib/content-freshness.ts`.
- `app/industries/recruitment-agencies/page.tsx`: 257-line **server component**. Sections: JSON-LD → hero (navy-700) → 5-bucket risk map (`BUCKET_DETAIL`) → how-the-scan-works (3 steps) → what-the-scan-checks (8) → FAQ (5, native `<details>`) → sidebar (assessment CTA, white-paper, briefings, consultation) → legal-baseline footer.

## Discovery Tool (taxonomy source of truth)
- `lib/discovery/`: `types.ts`, `data.ts` (access layer, `denormNiche()`), `data.generated.ts` (380 KB, generated by `tools/build-discovery-data.py`), `engine.ts` (+ tests), `checklist-map.ts`.
- Scale: **23 categories · 276 niches · 182 unique ItemDefs · 18 risk tags** (v3.0).
- Niche **`recruitment-staffing`** (cat `professional`, role B, risk high, phase 1): **23 items — 6 Core, 10 Operational, 7 Hidden** (e.g. WhatsApp/email attachments, rejected-lead archives, AI screening scores, processor access logs, ex-employee lingering access).
- Each ItemDef carries: `item`, `examples`, `tags`, `precaution`, `uiGroup`, `obligations[]`, `dataSubjects`, `processingPurposes`, `sources` (free-text `"; "`-joined). **This is a proto-flow-map** — the map adds the relational/flow layer Discovery lacks.
- Handoffs today: CSV inventory (lead-gated → Appwrite `template_downloads` + Resend email), checklist PDF per niche, plain link to `/assessment` (no state passthrough).

## Recruitment assessment pack
- `lib/data/industry-assessment/packs/recruitment-agencies.ts` (~540 lines): `reportType: "recruit"`, route `/assessment/recruitment`, **10 questions (q1–q10), caps Σ110**, **5 buckets**: `candidate_sourcing`, `candidate_document`, `client_sharing`, `ats_tool_access`, `retention_rights`. Badges red/amber/green (e.g. scraped profiles = HIGH RISK, overseas = CROSS-BORDER). LeadMagnet: recruitment starter-checklist PDF.
- Shared engine `lib/data/industry-assessment/{core.ts,bands.ts,index.ts}`; 12 sibling packs; **never edit core.ts/bands.ts** (isolation rule).
- Wizard has **no per-question anchors** (verified in `RecruitmentAssessmentClient.tsx` and older generic `components/assessment/AssessmentWizard.tsx`). Deep links land on the route, not a question.

## Graph/motion/animation
- **No graph library** (no react-flow/@xyflow, d3, dagre, cytoscape, visx). Graph = net-new; `@xyflow/react` approved as the single new dependency.
- `framer-motion@^12.38.0` **installed but zero usages** — available for motion without adding anything.
- CSS animation: `sp-dash-flow` / `sp-line-flow` keyframes in `app/globals.css` (used by `WhereRiskHides.tsx`, `HowItWorks.tsx`) **with `prefers-reduced-motion` disabling built in**; Tailwind keyframes `fadeUp`, `fadeIn`, `slideDown`.

## Analytics
- `lib/analytics.ts` — `trackEvent` object wrapping `window.gtag`, rich named events, extended per-feature (pattern: the `notice:` block). Used by assessment clients + discovery.
- ⚠️ **No gtag.js loader found** in `app/layout.tsx` — `trackEvent` guards on `typeof window.gtag` and may be a no-op in prod unless GTM injects it. Flagged in integration-risks; not this build's job to fix, but worth a check.
- Vercel Web Analytics mounted separately (cookieless page analytics).

## Backend
- Appwrite via `lib/appwrite.ts`: **lazy Proxy init** (mandatory — module-eval `new Client()` crashes `next build` on previews). 18 collections (leads, assessments, template_downloads, notice_*, dsar_requests, …). `assessments.report_type` is string(10).
- **v1 map needs zero Appwrite work** — static TS config, no persistence.

## Design tokens
- `tailwind.config.ts`: **navy** (primary; `brand` alias), **teal** (#35B6AE accent), **pearl** (page bg), green/amber/slate; custom shadows; Inter variable font. Icons: lucide-react. Card idiom: `rounded-xl border border-slate-200 bg-white p-5`.
- 12 industry hues in use = ceiling (per memory); the map must stay in the navy/teal idiom, no new visual system.

## Testing
- Minimal: `lib/discovery/engine.test.ts` exists; no repo-wide test runner config surfaced for components. Phase 1 validation tests will follow the discovery engine-test pattern; build-time Zod parse + `next build` are the backbone gates.
