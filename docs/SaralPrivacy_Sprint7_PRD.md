## 1. Context & Motivation

Two parallel initiatives are addressed in this sprint:

**Track A — SEO Hardening**  
A SEMrush site audit identified 5 warning categories affecting Googlebot's ability to crawl and index saralprivacy.com correctly. The most critical was 1,134 static assets (JS, CSS, images under `/_next/`) being blocked from Googlebot by robots.txt — this prevented JavaScript rendering, meaning Google could not see page content. Left unresolved, this suppresses organic rankings across all pages.

**Track B — Template Download (Standalone Page)**  
Templates were only accessible inside the tokenised assessment report (`/report/[token]`). A user who had not taken the assessment could not access templates. The whitepaper download (`/white-paper`) already exists as a standalone lead-capture page — templates need the same treatment at `/resources`.

## 3. Track A — SEO Hardening

### A1 — robots.txt Fix ✅ SHIPPED

**Problem:** `/_next/` was in the wildcard `Disallow` rule, blocking all JS, CSS, and image assets from Googlebot. Also `/consent-preferences` and `/rights/` were unnecessarily blocked (transparency pages that should be indexed). The `Host:` directive generated by Next.js is Yandex-only and produced a GSC warning.

**Solution implemented:**
- Removed `/_next/` from all disallow rules
- Removed `/consent-preferences` and `/rights/` from all disallow rules
- Added `/report/` as defense-in-depth (tokenised reports stay noindexed)
- Consolidated 11 duplicate disallow arrays into a single `COMMON_DISALLOW` constant
- Removed `Host:` directive (Yandex-only, Googlebot ignores it — was causing GSC warning)

**Files changed:**
- `webapp/app/robots.ts`

**Verification:** Production confirmed via curl. GSC "Request Indexing" submitted for homepage and 3 key pages. SEMrush rerun pending (24–48h).

---

### A2 — Long Page Titles Fix ⏳ PENDING

**Problem:** SEMrush flagged 14 pages with title tags exceeding 60 characters. Google truncates titles beyond ~60 chars in SERPs, reducing click-through rate and causing partial keyword loss.

**Known offender identified:**
- `/learn/dpdp-rules-2025-plain-english-guide` — title: `"DPDP Rules 2025: Section-by-Section Plain-English Guide | SaralPrivacy"` (72 chars)

**Requirement:**
- All `<title>` tags ≤ 60 characters
- Brand suffix `| SaralPrivacy` (14 chars) counts toward the limit
- Primary keyword must be front-loaded
- No truncation at brand name

**Format rule:** `[Primary Keyword — max 45 chars] | SaralPrivacy`

**Acceptance criteria:**
- Run `grep -r "title:" app/ | awk '...'` to confirm zero titles >60 chars
- SEMrush rerun shows 0 long-title warnings

---

### A3 — Broken External Images Fix ⏳ PENDING

**Problem:** 18 pages reference external image URLs that return 4xx/5xx errors. Broken images degrade page quality signals and user experience.

**Requirement:**
- Identify all `<img src="...">` and `next/image` references to external domains
- For each broken image: replace with a hosted equivalent, a placeholder, or remove
- If image is decorative and can be removed without content loss — remove it
- If image is editorial (e.g. blog post illustration) — replace with a self-hosted version in `public/`

**Acceptance criteria:**
- SEMrush rerun shows 0 broken-image warnings

## 4. Track B — Template Download (Standalone Page)

### B1 — Standalone /resources Page ✅ SHIPPED

**Problem:** Templates were only available inside the assessment report, requiring users to complete the full assessment first. Visitors who discovered templates via SEO or direct links had no way to access them.

**Solution implemented:**

**New component: `ResourceTemplateGate.tsx`**
- Completely independent of `TemplateGateModal.tsx` (report page component)
- Email address is a **mandatory** field (no existing credentials, unlike the report context)
- Same "fill once, all 5 unlock" gate logic using localStorage key `sp_rg_v1`
- Gate form fields: email, contact name, business name, employee count, phone, consent to contact, opt-in to briefings
- On submission: saves lead to Appwrite `template_downloads` collection with `source: "resources_page"`
- On success: triggers file download immediately, sets localStorage flag
- Subsequent visits: all 5 templates download directly without re-gating

**New page: `/resources`**
- Replaced previous redirect-to-blog stub
- Sections: header, trust strip (Free / No account / DPDPA-aligned / Instant download), 5 template cards, White Paper link, Assessment CTA
- Fully server-rendered page component with SEO metadata

**API update: `/api/template-download`**
- Added `source` field to document creation — distinguishes `"report_page"` from `"resources_page"` in Appwrite for analytics

**Files shipped:**
- `webapp/components/ResourceTemplateGate.tsx` (new)
- `webapp/app/resources/page.tsx` (replaced redirect)
- `webapp/app/api/template-download/route.ts` (source field added)
- `webapp/components/TemplateGateModal.tsx` (reverted — report page unchanged)

**What is NOT changed:** The report page (`/report/[token]`) and its `TemplateGateModal` are completely untouched. The two flows are fully independent.

### B2 — Template Download Email Delivery ⏳ PARKED (v2)

**Status:** WIP files exist on disk (untracked, never committed) — `TemplateDownloadForm.tsx`, `TemplateDownloadModal.tsx`, new `app/api/templates/download/route.ts`.

**What the WIP adds (beyond current):**
- Email delivery of download link via Resend (currently: file downloads directly in browser)
- WhatsApp delivery via Twilio
- File serving from Vercel Blob (not `public/templates/`)
- react-hook-form + Zod validation

**Why parked:**
- Adds Twilio dependency and cost for marginal improvement
- `@vercel/blob` needs files uploaded (operational overhead)
- Missing packages (`react-hook-form`, `@hookform/resolvers`) not yet in `package.json`
- Template ID mismatch between `validation.ts` and actual files needs reconciling
- WhatsApp delivery benefit is unproven — evaluate after `/resources` page shows traction

**Decision:** Ship simple version first (direct browser download), measure template download volume, then evaluate v2 upgrade in Sprint 8 or 9.
