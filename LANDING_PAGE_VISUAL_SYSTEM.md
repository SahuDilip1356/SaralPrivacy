## The one VV lesson
The DesignDisciplin post names 12 tactics (Scale, Comparison, Metaphor, Pattern, Flow, Stacking, Continuum, Venn, Hierarchy, Cartesian, Loop, Spectra) but — its own words — gives **no rules on constraint, consistency, colour, type, grid, or reduction.** That omission is the real moat: **VV's power is ruthless constraint + repetition of ONE system, not variety.** A 12-tactic / 8-asset "pack" is the *opposite* of VV. So the SaralPrivacy move is **subtract to one system + one signature concept, then repeat.**

## The visual system (the "kit" — assemble every diagram from this)
The way VV uses black-and-white, we use the **locked brand tokens (`LANDING_PAGE_STRUCTURE.md` §3c)** with VV-level rigidity.
- **Colour meanings locked, never reassigned:** navy = structure/ground · green = action / the one CTA / affirmation · **gold = risk/attention (never red)** · teal = secondary/hover · slate = body · cloud = light surface. Reader learns "gold = watch this" once; it's true everywhere.
- **Primitives (already converged in the how-it-works flow — that IS the kit):** one node (rounded-rect, icon + label) · one connector (dashed flow line) · one badge · one motion (slide-in + active flow) · hairlines not shadows · two type sizes per diagram · sentence case · Inter.
- **Anti-pattern to retire:** the live site's per-sector accent hue (12 colours). VV discipline → collapse toward *fewer, semantic* colours, not more decorative ones. (Hue-collapse is its own task; memory already flags "12 = ceiling.")

## Proposed direction (4 decisions — pending agreement)
1. **One signature visual = the data *scatter* ("where DPDPA risk hides"), NOT the generic lifecycle.** One node (customer) → lines fan to everyday tools (WhatsApp, Drive, Excel, CRM, CCTV, old archives) → a gold "gap" marker at each exit (consent/access/retention/vendor/evidence). VV-reduced (minimum geometry, not a busy infographic). Render ONCE, reuse on homepage + Discovery + deck + briefings + white paper. To show a sector, populate the *same* diagram — never a new one. _Lean: yes._
2. **Tokens-as-kit + start collapsing 12 sector hues toward semantic colour.** _Lean: yes; hue-collapse is a separate task._
3. **Beat 3 stays a LINEAR action ladder on the landing + a *quiet* loop-back hint** (the existing "keep it living" branch is already the monitor-arc; just make the return legible). The **full OPERATE loop** lives on the methodology/advisory page, not the landing. Two shapes for two intents: line = acquisition, loop = retention. _Lean: yes._
4. **Hard scope line: landing page only this cycle.** Everything else is captured below, sequenced by surface. _Lean: yes._

## Why scope-guard (not just effort): each surface answers a different question
| Surface | Visitor's question | Visual(s) that belong there | Phase |
|---|---|---|---|
| **Landing** | is it me? what do I do? | Flow (how-it-works) · "where risk hides" signature · before/after (policy vs readiness) | **NOW** |
| Assessment result | what does my score mean? | Readiness Stack · Continuum / readiness curve (0–100 bands) | Later |
| Industries / "Readiness Index" | where does my sector stand? | Risk-vs-Readiness Matrix (Cartesian) · Sensitivity Spectrum | Later |
| Discovery tool | where is my data? | Data scatter / lifecycle · Three Layers (core/operational/hidden) | Later / parallel |
| Methodology / advisory | how do I stay ready? | OPERATE Loop (the full cycle) | Later |
| Glossary / Guide | who's responsible? | Hierarchy (principal→fiduciary→processor→sub) · Control Map | Later |
| LinkedIn / content | hook + teach | 12 carousels · Risk Shadow · metaphors | Ongoing, separate |

**The one allowed exception to scope-guard:** the signature visual (#1) may recur across surfaces — it's the thesis, so "render once, reuse" is leverage, not creep. The guard is only against building *new, different* visuals per surface now.
